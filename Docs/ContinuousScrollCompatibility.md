# 连续上下滚动的首版兼容设计

## 产品约束与当前状态

用户明确反馈连续上下滚动的使用比例较高，因此它是 BonePageTurnKit 首版的核心兼容要求。本轮没有采集实际使用比例，不附加量化数字。

本文件保留首版完整兼容目标。第一个运行里程碑已实现独立纵向连续容器、异高窗口几何、锚点补偿、视图复用、旧绑定／旧窗口拒绝及稳定位置回调。后续已接入任务登记、延期安装、安装确认和唯一终态，以及页码／末页／最新内容边界，详见 [页码与加载记录](ReadingStatusAndLoading.md)。直接 apply 在交互中仍拒绝，异步任务通过 beginLoading／submit 等待空闲安装。下文未在里程碑中确认的真实宿主兼容机制仍属于后续验收要求。

后续已加入 [连续内容块契约与可读高度补屏](ContinuousContentContract.md)：跨块间距由内容侧计入一次，SDK 精确拼接；新结构化需求按 ready 覆盖判断，不以已加载块数或占位高度判定补足，并设自动请求／无进展／新增块预算。真实 App 的排版、交互和资源适配仍需单独验收。

需同时保留两种不同体验：

- **整页上下平移**：固定页高度，属于分页展示。
- **连续上下滚动**：内容可停在任意位置，跨正文块和章节连续浏览，对应现有 `.chunkScroll`。

不能以整页上下平移代替连续滚动，也不能把连续内容切成等高页面就认为完成兼容。

## 一、一个SDK，两套展示接口

```text
BonePageTurnKit
├── 共同基础：稳定身份、展示版本、生命周期、交互协调
├── Paged：固定页面供给、翻页效果、成功/取消事件
└── Continuous：内容窗口、可变高度布局、锚点补偿、滚动事件

宿主适配层
├── 文件、章节、正文解析与排版
├── 内容块视图和尺寸供给
├── 语义位置与展示锚点互相转换
└── 进度、笔记与设置持久化
```

初期保持一个SPM库产品，内部组织为不同职责。不要让分页模式必须实现连续章节接口，也不要要求连续容器为每一个正文块创建完整页面控制器。

## 二、责任边界

| 能力 | SDK | 宿主 |
| --- | --- | --- |
| 正文内容 | 挂载/复用宿主提供的内容视图 | 文件解析、章节组织、文本和图片渲染 |
| 数据窗口 | 管理可见和相邻内容、前插后追加、裁剪与锚点补偿 | 提供带稳定身份和版本的窗口更新 |
| 加载 | 提交前后边界需求，跟踪接受/安装/终止，防止重复请求 | 执行磁盘读取、排版或其他任务，提供取消与结果 |
| 占位/错误 | 展示宿主提供的占位内容，保持几何和位置 | 决定加载/错误原因、文案和重试动作 |
| 排版 | 接收高度及布局版本，计算容器几何 | 计算文本、PDF、图片尺寸，处理字体与行布局 |
| 阅读位置 | 暴露实际可见和稳定展示锚点 | 将展示锚点映射为字符/PDF等语义位置并存储 |
| 长按、链接、笔记 | 与内容交互协作，暂停/恢复滚动 | 选区、链接动作、标注与笔记管理 |
| 自动滚动 | 可选驱动、速度和暂停恢复；边界等待 | 用户配置、章节供给、是否为真正书尾 |

## 三、连续内容的最小数据契约

以下为概念字段，不是已确定的公开Swift类型。

- **Section ID / Item ID**：由宿主提供，生命周期内稳定且唯一；IndexPath只作当前布局地址。
- **内容版本 / 布局版本 / 展示代际**：内容变动、字体/宽度变动和新导航相互区分；结果安装前校验对应身份和版本。
- **内容块描述**：稳定ID、所属section、有限且合法的高度、ready/loading/error等状态、宿主可解析的内容引用。
- **边界状态**：前后方向分别表达可继续、等待、失败或确定到边界，不能以当前窗口没有下一项就判断全书结束。
- **视图生命周期**：创建或复用、绑定新内容、离屏、取消旧绑定、回收。异步图片/PDF结果只能更新仍绑定相同ID和版本的视图。
- **更新操作**：前插、追加、替换、删除/淘汰；每次更新在主线程一次性安装一致的item描述与高度。

已有 `KAPageStyle` 是引用对象，不能仅因外层数组固定就宣称整个对象图不可变。适配层应给SDK中性描述和受控视图接口，不把可变的正文模型公开为跨线程快照。

## 四、锚点必须区分展示位置与语义位置

连续锚点至少表达稳定item身份、item内偏移、该锚点在可视区域中的相对位置，以及产生它的内容/布局版本。宿主可以附带SDK不解释的语义定位值。

- **同内容、同布局恢复**：可以使用已验证的item内偏移或章节偏移。
- **分页↔滚动、改字体、改变宽度**：由宿主用章节标识和正文UTF-16位置等语义值重新定位；不要复用旧contentOffset或机械换算页码。
- **PDF**：由宿主提供页及页内位置映射，不能按普通文本字符定位处理。
- **明确跳转**：目录、搜索、书签和其他显式导航产生新的展示代际，不让历史偏移覆盖它。

现有实现依据：ParsingBook 中 `ReadChunkScrollPositionCoordinator.swift:175` 已按恢复意图区分锚点来源；`:222` 使用CoreText求目标行位置。后者属于排版适配能力，不应把CoreText正文模型强制写入通用容器契约。

### 跨模式切换流程

1. 从旧renderer获取有效的可见/稳定位置，排除回弹噪声与过期token。
2. 由宿主转换为语义位置，暂停旧renderer并取消旧代际任务。
3. 宿主按新模式准备页面或内容窗口；慢任务期间保留可靠占位或过渡画面。
4. 新renderer安装并确认目标内容可见后，再切换当前会话状态。
5. 旧回调不再影响新renderer；失败时保持可恢复状态，不保存错误的新位置。

固定页模式只能在分页精度内定位到包含目标文本的页面，不承诺所有模式像素位置完全一致。验收应检查语义内容对应和有限的视觉偏差。

## 五、窗口更新不能造成阅读跳动

前插章节、占位回填、图片高度变化或移除远端内容时，应先捕获当前可见锚点，再做更新并补偿几何变化，使锚点在屏幕上的位置保持。

仅有锚点上方内容高度变化时，可按锚点新旧内容坐标的差值调整contentOffset；锚点内部重排则需要宿主重新解析语义位置。不能统一用新增内容总高度处理所有情况。

拖动、减速、恢复锁或长按期间的结构更新，应遵循明确策略：可以安全补偿的更新原子应用；其余保留最新有效更新，在允许时安装。延期更新需要明确安装确认、覆盖、取消与终止状态，避免任务永久悬挂。

必须保留：

- 前插与后追加均可跨章，快速反向滚动不重复创建同一任务。
- 短章节连续补屏后仍停留在正确内容，不把预加载尾部当阅读位置。
- 已有可读内容不被迟到的loading/error覆盖。
- 旧内容/布局/展示版本的结果被拒绝；同一安装确认只消费一次。
- 窗口裁剪保留锚点与必要交互对象，控制内存，不加载整本书到视图树。

## 六、事件与交互

- `visibleChanged`类事件用于更新页眉页脚和实时进度，允许节流；不直接触发逐帧数据库写入。
- 稳定位置事件用于宿主持久化；拖动、减速、程序定位和退出的触发规则分别明确。
- 回弹、预热及恢复过程不得覆盖稳定保存位置；后台/退出时可请求一次有效位置快照。
- 长按拖选、外部退出、菜单等暂停原因不能相互覆盖。解除某个原因后，只在其余原因均解除且自动滚动原本运行时恢复；不要无条件开启滚动。
- 连续纵向滚动与上拉退出冲突，默认延续当前不启用上拉退出的策略；侧边退出要冻结并可恢复滚动状态。
- 自动滚动遇待加载边界先等待，确认书尾才结束；用户手动暂停不能被晚到加载结果擅自恢复。

对应现有机制包括 `ReadChunkScrollController.swift:193` 的有效可见位置、`ReadChunkScrollController+Position.swift` 的稳定提交，以及 `ReadChunkScrollController+Chrome.swift:419` 的长按暂停。迁移时保留行为，不机械复制App依赖。

## 七、渐进迁移与首版完成门槛

1. 先建立现有连续滚动的跨章、恢复和互切基线。
2. 同时设计Paged与Continuous协议，先跑无动画/覆盖加连续内容的最小独立示例。
3. 过渡阶段，App适配器可将滚动模式路由到旧ReadChunkScrollController，保证日常可用；不在SDK内导入ParsingBook类型。
4. 逐步把布局、窗口几何、锚点补偿和加载所有权搬到SDK；宿主继续提供正文视图、排版和语义定位。
5. 替换旧桥接后，独立示例与真实App都通过下面的兼容矩阵，才算首版完成。

允许内部开发里程碑先完成一个效果，但不能把只有固定页的版本视为满足本项目首版目标。持续使用旧App桥接也不能证明新App可以独立接入连续滚动。

## 八、必须验证的场景

| 场景 | 验收目标 |
| --- | --- |
| 普通滑动、惯性与边界回弹 | 顺畅连续，回弹不错误保存位置 |
| 连续跨多个短章、超长章分块 | 无错误跳章、卡在占位或无界视图增长 |
| 向上加载与窗口淘汰 | 内容在屏幕中的锚点保持，反向可继续浏览 |
| 慢排版、失败重试、迟到响应 | 状态可区分，旧结果不覆盖新内容 |
| 拖动/减速中占位回填 | 不意外跳动；延期更新能最终安装并释放所有权 |
| 图片/PDF高度变化 | 可见锚点正确补偿，复用视图不串内容 |
| 改字号、字体、旋转、分屏尺寸变化 | 语义位置重新解析，不套旧像素偏移 |
| 连续滚动↔覆盖/平移/仿真/拱页 | 定位到对应内容，往返不持续漂移 |
| 搜索/目录/书签跳转后立即滚动 | 最新用户导航有效，旧恢复任务不拉回 |
| 长按划线、段落点击、菜单与返回取消 | 手势互不抢占，暂停/恢复状态一致 |
| 自动滚动与加载边界、手动暂停 | 等待/结束可区分，暂停不被异步任务覆盖 |
| 退出、后台、重启与再次打开 | 恢复有效稳定位置，销毁后无迟到提交 |

性能对比应使用同一设备、同一合法样本、同一排版和窗口预算，比较抽离前后的卡顿、主线程工作、内存与位置偏差。本轮不设未经测量的帧率或耗时承诺。已有纯策略测试、源码约束测试和新增UIKit行为测试应分别记录，不能互相替代。

## 九、漫画连续阅读的补充候选

基于前期对 Aidoku 和 kmreader 的公开源码研究，连续容器应能承载异高图片页，并复用窗口更新和锚点补偿机制。研究报告作为本地资料保留；以下为当时的 SDK 设计建议，实现状态以 README 和后续接入文档为准。

- 区分稳定源页ID、当前展示单元ID与复用视图绑定代际；双页和拆片后仍能定位到原图区域。
- 图片尺寸未知时使用占位，尺寸到达后按当前交互状态安装并恢复锚点；不能将临时估计高度当最终位置基准。
- 同布局可以用页内偏移；宽度、缩放或展示组合改变时，由图像适配器解析源图坐标等稳定位置。使用归一化图像区域是候选方案，不把它当所有参考项目的既有实现。
- 放大或内容仍可pan时，外层翻页需让行。缩放、双击与单击/滚动相互协调，不能仅以zoomScale大于1判定是否占用。
- 预取与保留窗口分离，取消窗口外任务并拒绝旧结果。大图解码还需独立像素/内存预算；极长图可能需要分块，由宿主渲染适配器实现。
- 增加漫画单页、长条图、未知尺寸、前插章节、旋转、内存告警及模式互切的示例验收。双页/拆片策略作为扩展候选，不在本轮宣称完成。

不引入参考应用的书源、账号、网络或全局偏好系统，也不将其许可证、工具链或性能声明直接视为本SDK的兼容证明。
