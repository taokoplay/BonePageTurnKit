# 四角跟手仿真翻页

`.paged(effect: .curl, axis: ...)` 的原生拖动现在使用二维触点卷曲。横向可从上、下两个角分别揭起左边或右边的页；纵向对应上、下页边的左右角。横向 RTL 和显式书脊继续决定物理方向与逻辑 previous／next 的关系。供给边界仍由原 pageProvider 返回，不能从书首翻到不存在的前页。

## 手势与纸面

- 原生 pan 起步沿翻页轴的位移至少为横跨轴的两倍时，选择整页平翻；刚开始位移不足 4pt 时使用速度判断。底部、顶部和中间横拖都由手指方向选边，不再由所在纸角反向选边。
- 平翻在首帧前确定，小于等于 8pt 的横跨轴抖动保持整边平翻；随后出现明确斜向移动时，允许退出水平投影并持续跟随实际二维触点。转向时保留最初的抓取高度，避免突然跳到纸角；手指回到水平轨迹时，纸面也能回到整边平翻。明显斜拉起手继续使用纸角卷曲。
- 快速斜拖在首个原生提交前松手时，收尾保留最后手势的斜向意图，在原起点与原落点之间连续经过对应方向；仍使用原有时长和时间曲线。取消收尾及标量／离屏驱动保持原有轨迹。
- 宿主显式调用二维触点 API 时，角落仍锁定起角，中段保留抓取高度；原生斜拖呈现采用连续翻卷追随，停手后精确贴合。超出材料可达范围的触点会受约束，非有限更新保持上一帧。
- 角落与中部抓取先受书脊距离限制，再为圆柱展开弧长预留空间。普通可达触点保持绝对坐标，越界斜拖连续限位，避免交互边界退化为直硬平折；双页斜拖和回弹保持装订边固定。
- 原生 curl 手势允许斜向拖动，不再要求主轴速度大于横轴速度。嵌套滚动、缩放、业务门禁和选区的手势所有权规则保持有效。
- 正面、弧面和背面使用同一张材料的半平面裁切与圆柱投影。未折弯部分直接采样整图；曲面细分有固定上限。拖动中不重新捕获页面、不创建新的裁图位图。
- 正翻折起当前页，回翻沿用上一页逆向展开；回翻以当前页为底页，单页纸背保留移动纸张的底色与内容透印。双页保持原有正面与对侧背面映射，稳定正文及完成端点保持正向。
- 松手从当前纸角连续插值到完成或取消端点；反向速度优先取消。两个端点恢复真实内容控制器，仍由既有事务发出唯一 commit／settle。
- 触点慢拖有沿翻页方向的实际移动时，抓取点到达画布中线可完成；单页 curl 另接受目标页已显露至少半屏，即使手指位移很小。原生窗口采用最后提交的纸面姿态，首帧未提交不推断显示进度。原速度及距离条件仍有效，静止按下不翻页，快速反甩优先取消。

这是 SDK 自有几何与 Metal 实时绘制实现，不是系统 `UIPageViewController.pageCurl`。原生四角路径使用 GPU 批量绘制，保留 CoreGraphics 几何参考与不具备 Metal 时的同效果软件路径；程序化标量驱动和 arch 维持既有绘制。四角交互与系统原生卷页不构成逐像素或物理模型一致性承诺。真机性能测量与纸背材质修复见 [性能与材质](CornerCurlPerformance.md)。

## 宿主二维输入

内置 pan 自动启用。宿主提供外部手势时，使用 reader.view 的实际坐标：

```swift
// point 是手指按下位置，direction 由宿主根据阅读顺序决定。
if try reader.beginInteractiveTurn(.next, at: point) {
    // 每次移动时传完整二维坐标。
    reader.updateInteractiveTurn(to: movedPoint)
    // velocity 仍是沿本次逻辑翻页方向的速度，单位 point/s。
    reader.endInteractiveTurn(velocity: forwardVelocity)
}
```

`beginInteractiveTurn(_:at:)` 只用于 curl，其他效果抛出 `unsupportedPresentation`。非法、非有限或页外起点返回 `invalidInteractionPoint`，不安装候选内容；内容不可用、同步回调重入及尚未松手的交互继续沿用原门禁；curl 已松手后的收尾允许新翻页接管，详见下文。`updateInteractiveTurn(to:)` 只更新由触点入口开始的活动事务，不允许修改收尾中的曲面。

原 `beginInteractiveTurn(_:)`／`updateInteractiveTurn(displacement:)` 保持兼容，继续提供按进度驱动的纸面，用于程序化翻页、自动阅读和无触点预览。方向、版本、绑定与内容生成仍由既有 SDK 合约管理。

## 资源与生命周期

沿用两张原始快照的总像素预算和最大采样边长，`stripCount` 同时限制二维弧面的细分数量。二维几何最多包含该数量的弧段和两个平面区域。原生 Metal 路径不预裁 CGImage 条带；纹理上传后复用，三块有界顶点缓冲只在 GPU 处理完毕后复用。快照预算不包含 GPU 纹理副本、约 0.75 MiB 顶点缓冲、输出 drawable 或宿主内容。

取消、尺寸变化、暂停、退后台、退出和失效继续走统一清理路径。二维抓取状态随 pending 事务结束，不跨页复用。Reduce Motion 不创建纸面快照，也不改变逻辑翻页结果。

## 从折痕到自由纸角的渐变投影

投影改为随局部相对高度变化：贴近正文的折痕端窄而浅，沿纸边靠近翘起的自由纸角时逐渐变宽、变深。投影权重使用折痕／纸角的相对位置，结合曲面深度与平折接触带连续混合；在起角、落定附近连续淡出。纸背底色保持统一，投影仍落在未翻动的正文上。

`PaperCornerShadowGeometry` 为 Metal 与 CoreGraphics 参考路径生成同一份三角形网格。长边按高度变化有界细分，避免只插值少数轮廓顶点而削弱宽度渐变；内轮廓保持凸性，只向外扩展羽化带，避免细分后的内部三角形交叠产生色点。原生路径仍是一批顶点、一次 draw，不增加纹理或逐帧软件位图。既有前面 → 投影 → 纸背的合成顺序及资源清理保持不变。

## 中部起拖的二维跟随

中部起拖不再沿用一个固定纸角的单向位移限制。角落起拖仍锁定原起角；中段起拖则保留原始抓取高度作为材料基准，按当前横跨轴位移调整折痕。横向手势向下或向上移动、纵向手势向右或向左移动，都会改变同一张纸的实际折向。事务的物理起边和逻辑翻页方向保持锁定，途中换向不重新请求邻页。

抓取基准与用于轮廓投影的自由纸角分别计算，避免把中部手势简单切换到另一个页角。基准点到两端书脊的距离均受原材料长度限制；超过可达范围的手指位置连续钳制。当前跟手点直接对齐绝对触点；原按下点参与选角、抓取高度和手势意图计算，不叠加为显示偏移。逻辑位置保持一比一，原生呈现按下文的连续翻卷追随收敛；微小移动及中途换向保持连续。松手从当前受约束状态收敛，完成和取消端点仍恢复原始快照。

## 绝对触点贴手

原按下点到纸角／页边的距离不再叠加到当前触点上。逻辑控制点直接使用 `reader.view` 中的绝对输入位置，不再施加人工内抬或原始按下偏移；原生呈现按最新的连续翻卷追随设置跟随，停手后精确贴合。角落仍锁定起角，中段仍保留原始抓取高度；页外与书脊不可达位置继续限位，纸张不会因越界输入被拉离装订边。

纸面折起程度与手指实际移动进度分开计算。初始抓起时，纸面可直接到达当前手指位置；完成／取消仍按手指相对原按下点的实际位移和释放速度判断，因此中部短拖不会因初始纸面折起较大而误提交。原生 pan 在 `.began` 就同步当前触点，外部触点 API 在开始成功后也立即对齐。

新增回归独立检查实际输入坐标与材料投影，共覆盖 216 个几何位置；另在真实 GPU 图像中检测抓取边的小标记，36 个位置均满足 1.1 像素邻域要求。旧阴影基准以绝对坐标保持原实际落点，所有深浅／宽度断言保留，参考图像逐像素一致。

## 连续翻卷追随触点

手指更新位置时，逻辑触点仍按一比一绝对坐标记录，呈现目标改为一次约 180ms 的可重定向翻卷。目标更新不会立即修改当前纸面，也不会把它强制拉到距离目标八点以内；纸张从当前已提交姿态经过多个中间帧翻向最新触点。

沿用 SDK 既有三次 ease-out。手指继续移动时，只替换目标并以当前姿态重新起段；不返回原始页角，也不排队重播过时目标。重复传入同一目标不重启动画，停手后会有限时间准确到达该位置。新会话、取消和失效清空旧状态。

动画进度在取得 drawable 后计算，并且只有 GPU 提交成功才保留；没有可提交画面时不会在后台隐形追完。长停顿单个可见帧最多推进三十分之一秒，避免恢复绘制后直接跳到终点。时间模型与帧数无关，60Hz 和 120Hz 在相同推进时间的位置一致，高刷新率申请保留。
