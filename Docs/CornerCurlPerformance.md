# 四角卷曲性能与纸背材质

本次针对真机拖动卡顿与纸背三角形色差做了两项修复：原生四角路径改用 Metal 批量绘制；弧面与纸背平面使用统一材质及连续明暗。iOS 15、Swift 5、Swift tools 5.9 基线保持不变，没有新增第三方依赖。

## 原因及绘制路径

原实现把旋转折痕拆成多个多边形，在主线程为每块裁切 CGContext，再绘制一遍高分辨率整页纹理。斜向裁切和反复图像采样在真机上的耗时远大于交互帧预算。另有一层 12% 的页图叠加在纸背，且弧面末端与纸背平面的阴影不连续，表现为明显三角形色块。

新的 `PaperCornerMetalRenderer` 在翻页开始时上传两张快照，复用三组顶点缓冲区。每帧仍使用原来的有界二维几何，但正面、纸背、双页背面和轮廓阴影合成一批 GPU 三角形；不再在拖动中逐块重画 CPU 位图或预裁 CGImage。

`PaperCornerMetalView` 按屏幕刷新合并触点，GPU 忙时保留最新状态。drawable 获取在独立串行任务中完成，回主线程后重新校验当前视图仍活跃、窗口有效，再提交最新触点；取消或退出后的迟到 drawable 不会复活旧事务。获取等待不会阻塞主线程。纹理和顶点数据只在 GPU 命令执行完毕后复用。

初始化着色管线在 curl 容器加载时预热，随后复用；没有 Metal 的环境使用相同几何的软件路径。支持 Metal 的设备创建资源失败会明确拒绝本次准备，不静默改成别的翻页效果。旧标量驱动与 arch 维持原来的行为。

## 纸背颜色

单页弯起后的弧面和平面都使用当前纸张的同一底色，并以相同规则叠加当前页 18% 内容透印。纹理坐标随纸面反折，正反翻页均采样当前页；空白纸面保持原底色。弧面阴影在连接平面处连续收敛，因此不存在单独三角形的材质色差；自然弯曲阴影仍保留。双页背面仍来自目标对侧真实半页。浅色、深色、四个起角都用实际 GPU 输出检查，并与软件几何参考比较纹理方向和未翻动区域。

## 真机测量方法

使用独立的临时应用宿主运行 Release XCTest，设备为用户的 iPhone 13 Pro、iOS 26.5。固定 390×844 点、3× 输出，36 个测量帧与六个预热帧；两版都使用同一组文字页面、四角拖动路径和快照预算。旧版源代码保存在 scratch 中独立构建，未以优化后的代码重测旧版。

旧 CPU 计时包围 `UIGraphicsImageRenderer.image { paper.draw(...) }`，包含离屏上下文和软件绘制。新版分别记录 CPU 几何／编码／提交、GPU 命令执行以及含分配／等待／读回的离屏总耗时；原生交互不会执行读回。这些离屏时间不能直接换算成屏幕 FPS。

此外使用 `CAMetalDrawable.presentedTime` 记录 180 次显示刷新驱动下的实际呈现时间，去掉前六次呈现，记录 FPS、P95 间隔和超过 25 毫秒的间隔数。呈现时间采样仅在真机 SDK 中编译，模拟器不伪造硬件结果。性能测量默认关闭，不向产品界面添加调试流程。

## 渐变投影更新的验证范围

后续投影改为从折痕到自由纸角逐渐加宽、加深，Metal 与软件参考共享有界网格；仍使用原有纹理、顶点缓冲与一次 draw。长边按局部高度变化细分，内轮廓保持凸性，避免插值削弱宽度渐变或产生叠色接缝。33 项针对性检查通过，包含实际 GPU 像素、四角／两轴、取消／完成和主线程响应检查（`corner-shadow-taper-tests-v4`）。

此版本签名 Release 已安装到 iPhone 13 Pro。额外 ProMotion 测量在测试体启动前被密码锁屏阻塞，结束等待后的宿主结果为 Testing was canceled；没有新的 CPU／GPU 耗时或实际呈现 FPS。上表 59.995 fps 数据仍仅属于先前 Metal 初版的构建和工作负载。当前版本的安装、构建输入一致性及测量阻塞保存在 `corner-shadow-taper-final-verification.json`，未将最高刷新率请求视为实际帧率。

## 纸背文字恢复

单页纸背已恢复当前页 18% 淡透印，弧面和平面使用相同采样与混合；复用已上传的当前页纹理，仍是单批次绘制。34 项针对性回归通过，包含明暗主题、四角、两轴的实际 GPU／软件字形对齐和空白底色检查，以及既有渐变投影和生命周期检查（`corner-back-text-tests-v2`）。已查看 16 张实际 GPU 图，签名 Release 已更新到 iPhone 并核对到运行进程。本轮未额外测量硬件帧率，历史性能数据保留原构建范围。

## 完整 Reader 链路的丝滑度优化

本轮以恢复后的四角／回翻模型及“目标页实际可见面积过半可完成”规则为基线。保留 180ms 可重定向跟手、约 288–360ms 离散翻页、快速连续翻页最低 0.8 倍时长、交互收尾 1.2 倍时长和既有曲线；快照预算、曲面细分、纸背文字及阴影质量保持原值。

- 原生 Metal 收尾由渲染时钟在同一次刷新中先推进 Reader、再获取和提交 drawable，消除两只独立时钟相位造成的隔帧机会。首帧、末帧提交确认及 GPU 忙碌时的门控继续生效；手动、软件和旧标量路径保留原驱动。
- 相邻翻页交接目标页的 CGImage 与已上传纹理。纹理必须对应同一个 CGImage、同一 Metal 设备及相同尺寸；首笔上传两张，缓存有效的后续一笔只上传新目标页。缓存还检查页面身份、展示身份、尺寸、预算及 traits；正文替换、正文排版失效、尺寸变化、内存警告和 renderer 失效会清理缓存。
- 已挂载的原生 Metal 逐帧路径只在实际变化时写真实页面的 frame／isHidden，避免无变化的 UIKit 布局回调；每个可能重入的写入后继续校验事务身份。
- 曲面复用带锁的不可变条带角度表与局部裁切暂存区，移除已按深度单调生成的重复排序；阴影共用投影和极值归约。保持原浮点运算次序与几何公式，并用冻结旧算法验证补丁字段、顺序、阴影顶点、可见面积及全部受支持细分数量。
- Demo 等待有效排版宽度后再构建富文本，避免首次宽度为零时的重复准备。

`ReaderSmoothnessBenchmarks` 通过完整 `PagedReaderViewController` 测量三次前翻、三次回翻，固定 390×844、标准 4,194,304 像素预算和 128 条带。Release 独立宿主分别链接冻结旧 SDK 和当前 SDK；实际 FPS 来自 `CAMetalDrawable.presentedTime`，与独立观察时钟回调数、提交数分别记录。测试宿主需先稳定处于前台，每笔必须完整落定、达到完整计划时长和最终进度；启动中断或前置状态检查失败的整轮不作为最终对比。
